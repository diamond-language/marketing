Diamond is a typed, object-oriented language. The compiler checks the annotations you write, a register VM with an optional JIT runs the result, and diamond build turns a program into one executable — cross-compiled, or fully static if you like. Threads copy values instead of sharing a heap.

    Familiar ground

    You have probably written something like this

    Pieces of Diamond will feel familiar depending on where you are coming from. The names are different; the ideas are not new.

    Blocks, classes, and end

    Classes, mixins, blocks and end-delimited bodies, with an expressive object model. Types are optional annotations layered on top, checked when you write them.

    class Order
  include Comparable

  def initialize(total: Int)
    @total = total
  end

  def <=>(other: Order) = @total <=> other.total()
  def total() = @total
end

orders = [Order.new(30), Order.new(10), Order.new(20)]
orders.sort().map() do |order|
  order.total()
end
# => [10, 20, 30]

    Real threads, light fibers

    A Thread is an OS thread with its own heap. Ordinary objects are copied across thread boundaries; channels coordinate communication. Fibers give you generators and coroutines inside one thread.

    left = Thread.new(square, 6)
right = Thread.new(square, 7)
left.join() + right.join()   # => 85

steps = Fiber.new(countdown)
steps.resume()   # => 3
steps.resume()   # => 2

    Mailboxes and supervisors

    Threads talk through bounded channels, and a supervisor restarts a worker that crashes. With the default one-for-one policy, the other workers keep running. This excerpt uses application-defined producer and fetch_loop functions.

    jobs = Channel.new(4)
worker = Thread.new(producer, jobs)

item = jobs.receive()   # blocks until a value arrives

sup = Supervisor.new()
sup.add_child(fetch_loop)
# fetch_loop crashes? it is restarted;
# nothing else is touched

    Packages you install, not frameworks you adopt

    Mjolnir is a data mapper: entities are plain structs, queries are values, and one Repo does the I/O. HTTP servers, routing, GraphQL, jobs, Redis and WebSockets are packages too.

    struct User(id: Int, name: String, email: String)
end

users = Mjolnir::Schema.new("users",
  {"id": :int, "name": :string, "email": :string},
  build_user)
repo = Mjolnir::Repo.new(db)

changeset = Mjolnir::Changeset.cast(users, nil, attrs,
    ["name", "email"])
  .validate_required(["name", "email"])
  .validate_format("email", "@")

case repo.insert(changeset)
when Mjolnir::Ok  then "saved"
when Mjolnir::Err then "rejected"
end

    Recent changes

    New source extensions, rendezvous channels, and more precise editor tooling in 0.19.0.

    Source files use .d6

    .d6 is the default extension, with .d6c caches. Existing .di files and published cuts still load. When both files exist, an extensionless import chooses .d6.

    # helper.d6 defines answer() = 42
# helper.di defines answer() = 99
require "helper"
answer() # => 42

    Rendezvous channels

    A zero-capacity channel transfers a value directly to a waiting receiver. The sender waits until the value has been taken.

    def deliver(ch)
  ch.send(42)
end
ch = Channel.new(0)
worker = Thread.new(deliver, ch)
ch.receive() # => 42
worker.join()

    Editor and runtime fixes

    The language server tracks receivers through imported collections, guards, and helper return values more precisely. UTF-16 positions keep navigation aligned after emoji and accented text.

    REPL output now survives later submissions, and object patterns on high-numbered classes count correctly toward exhaustive case checks.

    What it is

    Strict where you ask, quiet where you don't

    The syntax will look familiar if you have written scripting languages. What it does with it is its own: checked annotations, copy-only concurrency, a sandbox in the interpreter, and deploys that are a single file.

    Every call needs parentheses

    puts("x"), not puts "x"; Foo.new(), not Foo.new. No bare-call form, no ambiguity about what's being invoked.

    Types are optional, but real

    Annotations, union types with nil narrowing, generics, and structural interfaces (no implements — any matching class satisfies one) are checked at compile time, not just documented.

    Compiled, not just interpreted

    A Pratt compiler emits register bytecode for a VM with inline caches, object shapes, and quickening. diamond build produces a standalone native executable — no interpreter needed at runtime.

    No shared mutable state

    Threads use isolated heaps; values copy across boundaries. A Channel gives threads an ongoing mailbox, and a Supervisor restarts a crashed worker automatically — Erlang's one_for_one, not exception handling.

    Sandboxing built into the language

    diamond --sandbox denies filesystem, network, and subprocess access for running untrusted code — checked at each opcode, not bolted on with a wrapper.

    No general eval

    ClassName.compile_method compiles a capture-free method body from a source string — there's no arbitrary code evaluation in the calling scope.
    Under the hood

    From source to native code

    One flat compile per program, checked types, then an interpreter and a JIT that share one VM. The same compiled bytecode feeds the on-disk cache and diamond build.

    1. 01

      Load

      require and require_cut splice every file into one source buffer. There is no separate compilation unit.

    2. 02

      Compile

      A discovery pass collects declarations; a Pratt compiler then checks annotations, unions, generics, and exhaustive case.

    3. 03

      Bytecode

      About 170 opcodes over 16-bit register operands, cached in a fingerprinted .d6c file next to the source.

    4. 04

      Interpret

      Inline caches, object shapes, and quickening on a VM with a generational, nursery-based garbage collector.

    5. 05

      JIT

      The opt-in JIT compiles hot typed functions on glibc Linux x86-64. Other platforms and unsupported operations use the interpreter.

    Ship a binary

    diamond build embeds the compiled program in a native executable. An installed toolchain links it against a prebuilt runtime kit with one compiler call.

    Isolated threads

    Each Thread runs its own VM and heap. Arguments, results, and Channel messages are deep-copied. Channel handles are shared deliberately so threads can coordinate without sharing an object heap.

    Capability sandbox

    --sandbox checks filesystem, network, and subprocess access at each native opcode, with resource budgets and a per-capability allow-list.

    Tooling in the box

    A language server, a Debug Adapter Protocol step debugger, a formatter, and a lexer and parser written in Diamond itself.

    See it in action

    The same language, five angles

    Classes and mixins, generated structs, exhaustive pattern matching, real OS threads and cooperative fibers, and a sandboxed runtime.

    point.d6
    struct Point(x: Int, y: Int)
end

p1 = Point.new(1, 2)
p2 = Point.new(x: 1, y: 2)
p1 == p2               # true
p1.to_s()              # "Point(x: 1, y: 2)"

# initialize/readers/==/to_s are generated -- gradual
# types and nil narrowing work the same as anywhere else
def choose(flag: Bool, value: Point | Nil) -> Point | Nil
  if flag
    value
  else
    nil
  end
end

    struct Name(field: Type, ...) ... end generates initialize, readers, ==, and to_s — and still composes with include, hand-written methods, and union types.

    classify.d6
    def classify(value: Int) -> String
  case value
  when 0
    "zero"
  when 1, 2, 3
    "small"
  when 4..10
    "medium"
  else
    "large"
  end
end

    Matching over a union or a sealed class hierarchy is checked for exhaustiveness at compile time — an uncovered case is a compile error, not a runtime surprise.

    workers.d6
    # Thread: real OS threads, each with its own isolated
# heap -- runs in parallel across CPU cores

def square(n) = n * n

left = Thread.new(square, 6)
right = Thread.new(square, 7)
left.join()   # => 36
right.join()  # => 49

# Channel: an ongoing mailbox between isolated-heap threads
def producer(ch) = ch.send(42)
ch = Channel.new(64)
worker = Thread.new(producer, ch)
item = ch.receive()
worker.join()

# Supervisor: restart-on-crash, Erlang's one_for_one
sup = Supervisor.new()
sup.add_child(producer, ch)
ch.receive() # => 42
sup.join()
# a child that raises is restarted; completed children stay done

    Ordinary values crossing a thread boundary are copied. Channel handles are shared for communication between isolated heaps.

    counter_fiber.d6
    def make_counter()
  def counter()
    i = 0
    loop do
      increment = Fiber.yield(i)
      i = i + increment
    end
  end
  counter
end

counter = Fiber.new(make_counter())
counter.resume(0)     # => 0
counter.resume(10)    # => 10
counter.resume(5)     # => 15

    Cooperative concurrency within a single OS thread — a fiber runs until it finishes or yields, never preempted in between. Reach for Thread instead when work should actually run in parallel across cores.

    shell
    # denies filesystem, network, and subprocess access --
# checked at every native opcode, applies to anything
# the program spawns (Thread, Supervisor) too
diamond --sandbox untrusted.d6

# equivalently:
DIAMOND_SANDBOX=1 diamond untrusted.d6

    Sandboxing for running untrusted code, not a wrapper script around the interpreter.

    Featured cut

    Mjolnir

    A stateless data mapper on Arel. Entities are plain structs, queries and validation are values, and one Repo does all the I/O.

    No hidden work

    • Changesets whitelist, cast and validate untrusted input before anything touches the database.
    • Queries are immutable. Every method returns a new one, and a misspelled field raises instead of generating bad SQL.
    • Results are sealed. A case over Ok and Err is checked for exhaustiveness.
    • No lazy loading. An association is fetched only by preload, one query for any number of entities.

    After building Diamond and Facet below, start a new project directory:

    mkdir demo && cd demo
facet init demo
facet add mjolnir --registry https://cuts.dilang.tech --version "^0.3.1"
facet install

    Queries and associations

    Declare associations once, then load them explicitly. Database access is explicit; query counts depend on the operation and database dialect.

    users.has_many("posts", posts, "user_id")

matching = users.query()
  .where(users.column("name").eq("Ada"))
  .order_by("name")
  .limit(10)

listed = repo.all(matching)
repo.preload(users, listed, "posts")
# => {1: [Post, Post], 2: []}

repo.transaction() do |tx|
  tx.insert(changeset)
end
    Install

    Build it, run it, ship it

    Diamond compiles from source today. Bytecode is cached automatically between runs, and diamond build produces a self-contained native binary when you're ready to ship. A C23 compiler with #embed support is required (GCC 15+ or Clang 19+). On x86-64, the supported baseline is x86-64-v3 (AVX2, BMI2, FMA). Pick your platform to get started.

    Fedora is the maintainer's own dev machine and Ubuntu runs Skindicate in production, on top of both getting full CI coverage. Alpine, FreeBSD, and macOS are currently validated on GitHub Actions only — if you hit a problem there, please open an issue or a PR.

    Fedora
    # Install system dependencies
    sudo dnf install git make gcc openssl-devel sqlite-devel libpq-devel \
    mariadb-connector-c-devel libxcrypt-devel zlib-devel
    # Download the source
    git clone https://github.com/diamond-language/diamond.git
    cd diamond
    # Build Diamond
    make all facet

    LDFLAGS_EXTRA='-L/usr/local/lib -L/usr/local/lib/mariadb'

    # Install Xcode command-line tools and Homebrew first; Clang 19+ required
    brew install coreutils gnu-sed bash openssl@3 sqlite postgresql@16 mariadb-connector-c
    export PATH="$(brew --prefix coreutils)/libexec/gnubin:$(brew --prefix gnu-sed)/libexec/gnubin:$(brew --prefix bash)/bin:$PATH"
    # Download and build Diamond
    git clone https://github.com/diamond-language/diamond.git
    cd diamond
    make all facet CC=clang LDLIBS_CRYPT= \
    CPPFLAGS_EXTRA="-I$(brew --prefix openssl@3)/include -I$(brew --prefix sqlite)/include -I$(brew --prefix postgresql@16)/include -I$(brew --prefix mariadb-connector-c)/include -I$(brew --prefix mariadb-connector-c)/include/mariadb" \
    LDFLAGS_EXTRA="-L$(brew --prefix openssl@3)/lib -L$(brew --prefix sqlite)/lib -L$(brew --prefix postgresql@16)/lib -L$(brew --prefix mariadb-connector-c)/lib -L$(brew --prefix mariadb-connector-c)/lib/mariadb"
    run & ship -- same on every platform
    # Make Diamond and Facet available in this shell
    export PATH="$PWD/build:$PATH"
    # Run a one-liner
    ./build/diamond -e '20 + 22'
    # => 42
    # ...or run a file
    printf 'puts("Hello, Diamond")\n' > program.d6
    ./build/diamond program.d6
    # ...or start the REPL
    ./build/diamond
    # Ship a standalone binary -- no interpreter needed at runtime
    ./build/diamond build program.d6 -o app
    ./app
